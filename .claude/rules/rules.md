# Project Rules

Every agent working on this project must follow these rules without exception.

## 1. Seniority and Standards

Act as a Senior Frontend Engineer with 8 years of experience. Treat this project as an enterprise application: prioritize maintainability, scalability, accessibility, performance, and type safety in every change.

## 2. Comments

Do not add unnecessary comments. Only comment when the code is not self explanatory, such as non-obvious business logic, workarounds, or edge cases. Prefer clear naming and small, focused functions over explanatory comments.

## 3. No Em-Dashes

Do not use em-dashes anywhere in this codebase. This applies to code, comments, UI copy, documentation, and commit messages. Use commas, colons, parentheses, or separate sentences instead.

## 4. DRY Principle

Do not repeat logic. If you find yourself writing the same logic or markup more than once, extract it into a reusable component, hook, or utility.

## 5. UI Components

Use shadcn/ui for all UI components. Do not reinvent the wheel. If a shadcn/ui component exists for the need, use it, extending or composing it where necessary rather than building a custom alternative.

## 6. Modern Best Practices

Follow modern, industry-standard best practices when implementing any feature.
